# OmniForge: missing features, requirements and improvements

*Analysis date: 2026-10-16. Grounded in `W:\Work\Projects\OmniForge` at commit `4ae443d` (README, docs/product-design.md, app/*.py, dashboard.html, tests) plus a throwaway local instance used to confirm transport and runner behaviour. Nothing was edited, committed or deployed.*

## Executive summary

OmniForge today is a well-tested **single-user authoring surface** with a careful dashboard (dirty-state guards, revision conflicts, PWA hygiene, accessibility) sitting on a **thin, unsafe core**. The product's own copy is honest about this, and the code confirms it:

1. **Secrets leak by construction.** `runner.run_tool` copies the whole process environment into every script; a one-line tool printed `OMNIFORGE_API_KEY` on the local instance. Scrubbing the environment (R-04) is a one-line fix and is the prerequisite for any vault (F-05).
2. **One running tool freezes the server.** `api_run_tool` and `mcp_endpoint` are `async def` that call blocking `subprocess.run` and the 120 s installer inline, so the dashboard and every MCP client stall for the duration (R-08). Output is unbounded (5 MB passed straight through, R-07) and timeouts kill only the direct child (R-06).
3. **The MCP transport is hand-rolled and non-conformant** while the official `mcp` SDK is already installed and unused: notifications get error replies, batches 422, `initialize` echoes any version, no sessions/Origin check/`list_changed`. Adopting the SDK (I-01/R-09) fixes a dozen findings at once and unlocks prompts, resources, structured results and n8n/Claude compatibility.
4. **Nothing can be undone or recovered.** No version history, no run logs, no export, no backup, no schema migration, and the dashboard cannot even edit an input schema (every browser-authored tool is parameterless, F-02).
5. **Auth is all-or-nothing.** One shared key gates `POST /mcp` only; the dashboard, management API and `GET /mcp` are open. Named scoped keys plus a session login (R-01/R-02) are the floor; OAuth 2.1 (R-03) is what hosted Claude.ai connectors need.
6. **For beginners** the biggest wins are cheap: per-client connection recipes (LibreChat YAML, `claude mcp add`), a plain-language error catalogue, realistic examples that actually fetch something, and a secure first-boot setup screen.

**Recommended order:** week 1 quick wins (R-04, R-06, R-07, R-08, I-03, R-18, R-19, R-20, U-04, B-02) -> SDK transport (I-01/R-09) -> auth (R-01/R-02/B-03) -> history/export/backup (F-01/F-03/R-12/F-06) -> schema editor and wizard (F-02/B-01/U-02) -> sandbox (R-05/R-17) -> automation and advanced (F-07/F-08/A-08/A-04/F-04).

Counts: 84 items (20 features, 22 requirements, 12 improvements, 12 usability, 7 beginner, 11 advanced).

Legend: effort S/M/L; value low/medium/high; priority P1 (do first) / P2 / P3.


## What the code actually does today (facts the items rely on)

- **Surface:** FastAPI (`app/main.py`), routes `/`, `/assets/*` (literal allowlist), `/sw.js`, `/api/config`, `/api/tools` CRUD + `/toggle` + `/run`, `POST /mcp` (initialize, tools/list, tools/call, ping), `GET /mcp` (fake `initial-connections` SSE event, no auth).
- **Auth:** one `OMNIFORGE_API_KEY` compared in `_check_api_key` on `POST /mcp` only; empty key = no auth. Dashboard/API: none. `/api/config` reports `dashboard_auth_enabled: False`.
- **Runner:** writes `SCRATCH_ROOT/{tool.id}.py|js`, `subprocess.run([runtime, file], input=json, capture_output=True, timeout=MAX_TIMEOUT_MS/1000+15, cwd=SCRATCH_ROOT, env=os.environ.copy()+PYTHONPATH/NODE_PATH)`. No rlimits, no process group, no output cap, memory setting unused. Called synchronously from async handlers.
- **Dependencies:** per `(tool-id-hash, language, requirements-hash)` directory under `OMNIFORGE_LIB_ROOT`, fcntl lock, 120 s install timeout, wheels-only pip / `--ignore-scripts` npm, minimal env for installers only, `.complete` marker, old caches never pruned.
- **Storage:** single `tools` table, non-unique name index, `BEGIN IMMEDIATE` uniqueness guard, content-hash `revision` for `If-Match` (412), per-process 5 s list cache. No versions, runs, keys, audit, schema_version.
- **MCP handler:** built-ins `omniforge_instructions` and `omniforge_create_tool` (save-only); results are one text block with `isError`; `listChanged: false`; `initialize` echoes client version. `mcp`, `sse-starlette`, `slowapi`, `pydantic-settings` in requirements.txt are unused.
- **Dashboard:** 574-line single HTML with inline JS; hash routes; textarea editor with gutter; schema read-only ('Create or change schemas through MCP'); test inputs = raw JSON textarea; run output in tab memory only; four examples; Connect shows origin + one HTTP template; `Connected clients: Not tracked`.
- **Build/ops:** `python:3.12-slim` + Debian `nodejs npm` (Node 18), UID 1000, no HEALTHCHECK; CI tests on PRs/non-main only, Docker Hub push on main without test gate; compose image name differs from CI; dead `OMNIFORGE_RUNTIME_IMAGE`/`SCRIPT_HOST`/`omniforge_scripts` volume.
- **Tests:** strong on dashboard races, revision conflicts, dependency caching, PWA cache rules, axe accessibility; nothing on secret leakage, process trees, output size, concurrency, or MCP conformance with a real client.
